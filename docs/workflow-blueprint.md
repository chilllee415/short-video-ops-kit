# 商用短视频运营工作流蓝图

## 核心原则

公共模板不要从“生成选题”开始，而要从“账号诊断”开始。

完整链路：

```text
账号数据输入
  -> 自动运营诊断
  -> 策略候选
  -> 用户确认策略
  -> 赛道参考拆解
  -> 场景雷达
  -> 选题推荐
  -> 内容执行
  -> 数据回收
  -> 下一轮权重更新
```

## 为什么策略确认必须存在

同一个账号的下一步目标可能完全不同：

- 拉播放：优先成果前置、强演示、低理解成本。
- 拉私信：优先痛点诊断、CTA 明确、服务边界清晰。
- 建信任：优先案例解释、过程透明、反常识判断。
- 卖服务：优先高付费可能、高产品化、可交付路径。

如果不确认策略，系统会把“看起来会火的题”和“真正服务目标的题”混在一起。

## 标准产物

- `account-snapshot`：账号运营诊断快照。
- `strategy-brief`：策略确认单。
- `reference-mining`：对标内容拆解和选题复刻素材。
- `topic-candidates`：周度场景选题雷达。
- `feedback-learning`：发布后反馈与权重更新记录。

## 解耦方式

工作流之间使用产物依赖，不使用脚本互相调用。完整依赖图见 `workflow-dependency-graph.md`。

```text
下游工作流只读取上游产物。
上游产物缺失时，下游输出缺失报告或降低置信度。
只有总编排脚本可以连续调度多个节点。
```

## 自动化策略

完整自动化逻辑见 `automation-business-logic.md`。

当前只保留三类常驻自动化：

```text
每天更新运营大盘和作品表现
每 2 天更新爆款素材库
每周做用户需求调研
```

选题推荐、脚本生成、账号方向复盘默认手动触发。

原因：

- 运营数据和作品表现是稳定数据维护，适合每天自动跑。
- 爆款素材库是持续资产积累，适合定期自动跑。
- 用户需求调研是策略输入，适合周度沉淀。
- 选题、脚本和账号方向强依赖当前创作意图，必须保留人工选择和确认。

## 策略更新边界

`pain-bank.json`、`feedback-learning.json`、`reference-bank.json` 都可以影响账号策略，但不能直接覆盖账号策略。

正确流程：

```text
需求/反馈/参考素材变化
  -> 输出 strategy-impact 或 strategy-delta
  -> 用户确认
  -> 手动更新 strategy-brief
```

任何自动化都不得直接写回 `config/strategy/strategy-brief.json`。

## YouTube 二创型选题链路

针对 Codex、AI coding agent、AI automation 这类英文信息源，推荐增加一条专门链路：

```text
策略确认
  -> 读取 pain-bank 和 strategy-brief
  -> 配置关键词和竞品频道
  -> 采集 YouTube 候选源
  -> 拆标题结构和内容结构
  -> 中文用户场景重写
  -> 自己录屏验证
  -> 汇总给用户挑选
  -> 进入周度选题池
```

这个链路的目标不是翻译视频，而是把英文内容里的有效结构改写成中文用户能理解、能信任、能咨询的短视频选题。
